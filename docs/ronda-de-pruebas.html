Sistema de Gestión de Turnos Médicos · Backend

Ronda de pruebas

Guía para probar lo que se subió esta semana. Está escrita para alguien que nunca usó una terminal ni Postman — vamos a explicar cada botón, cada palabra rara y cada ventana. No hace falta saber programar, solo ir siguiendo los pasos en orden.

0/12 pasos marcados

Antes de arrancar: 5 palabras que vas a ver todo el tiempo

Backend
El programa que corre en tu propia computadora y contesta las preguntas que le hacemos (por ejemplo "dame la lista de pacientes"). Pensalo como la cocina de un restaurante: Postman es el mozo que pide, el backend es la cocina que prepara la respuesta. Si la cocina está cerrada (el backend no está prendido), no importa cuántas veces pidas: nadie contesta.
Terminal
Una ventana negra (o gris) donde en vez de hacer clic, le escribís órdenes a la computadora con el teclado y apretás Enter. La vamos a usar solo para prender el backend.
Postman
Un programa con botones que te permite "hacerle preguntas" al backend sin escribir código. Es la herramienta principal de esta guía.
Token
Una especie de pulsera de acceso digital. Cuando iniciás sesión, el backend te da un token; se lo mostrás en cada pedido siguiente para probar quién sos, sin tener que escribir tu contraseña de nuevo cada vez.
Código de estado
Un número de 3 cifras que viene con cada respuesta. 200 o 201 = salió bien. 401, 403, 404, 409 = algo esperable no se cumplió (te explicamos cuál es cuál en cada paso).

Qué tenés que tener abierto o instalado

  • El proyecto abierto en VS Code (el editor de código), con el código actualizado (git pull de la rama que te pasaron).
  • PostgreSQL corriendo en tu máquina (es la base de datos — normalmente se prende sola cuando arranca Windows, no hace falta que hagas nada).
  • Tu archivo application.properties completo (te lo tienen que haber ayudado a armar antes; si no lo tenés, avisá antes de seguir).
  • Postman instalado. Si no lo tenés: entrá a postman.com/downloads, descargalo e instalalo como cualquier programa (Siguiente, Siguiente, Instalar).
1

Encontrar la terminal dentro de VS Code

La vas a necesitar para el paso 2

Con el proyecto abierto en VS Code (si no lo está: File → Open Folder y elegís la carpeta gestion-turnos-database):

  1. Mirá el menú de arriba de todo de la ventana de VS Code.
  2. Hacé clic en Terminal (entre "Run" y "Help").
  3. Hacé clic en New Terminal (Nueva terminal).
esperado
Se abre un panel abajo de todo de la pantalla, con letras y un cursor titilando. Ahí es donde vamos a escribir en el paso 2. Si ya tenías una terminal abierta de antes, esa misma sirve.
2

Levantar (prender) el backend

Escribí esto en la terminal que abriste en el paso 1

"Levantar el backend" significa: prender ese programa para que quede escuchando pedidos. Escribí la primera línea, apretá Enter, esperá que termine, escribí la segunda línea y apretá Enter:

cd backend
.\mvnw.cmd spring-boot:run

cd backend quiere decir "entrá a la carpeta llamada backend". La segunda línea es la que efectivamente prende el programa.

esperado
Van a pasar muchas líneas de texto rápido — no hace falta leerlas. Esperá (la primera vez puede tardar más de un minuto) hasta ver una línea parecida a Started BackendApplication in ... seconds. Eso confirma que quedó prendido.

Importantísimo: no cierres esa terminal ni apretes nada ahí adentro después de esto. Dejala abierta de fondo (podés minimizar VS Code) y pasate a Postman para el resto de la guía. Si la cerrás, el backend se apaga y Postman deja de poder conectarse.

3

Abrir Postman y traer los pedidos ya armados

Una sola vez — después queda guardado

Abrí el programa Postman (buscalo como abrirías cualquier programa, por el ícono o desde el buscador de Windows). Si te pide crear una cuenta o iniciar sesión, se puede omitir ese paso ("Skip" / "Continue without account") — no hace falta cuenta para lo que vamos a hacer.

  1. Arriba a la izquierda, buscá el botón Import y hacé clic.
  2. Se abre una ventana. Hacé clic en Choose Files (Elegir archivos).
  3. Buscá, dentro de la carpeta del proyecto, el archivo docs/turnos-medicos.postman_collection.json y seleccionalo.
  4. Hacé clic en el botón azul Import para confirmar.
esperado
A la izquierda te aparece "Turnos Médicos", en la pestaña Collections. Hacé clic en el nombre para desplegarlo — vas a ver carpetas como "Auth", "Financiadores", "Coberturas", etc. Cada una tiene adentro los pedidos ya armados, con la dirección y los datos cargados. No vamos a escribir ningún JSON a mano en toda esta guía.
4

Mandar tu primer pedido: iniciar sesión

Carpeta Auth → Login (paciente - Juan Pérez)

Desplegá la carpeta Auth (clic en el nombre) y hacé clic en Login (paciente - Juan Pérez) — se abre en el panel principal, a la derecha.

  1. Arriba vas a ver POST y una dirección terminada en /auth/login — es a dónde se manda el pedido. No hace falta tocar nada.
  2. Buscá el botón azul Send, arriba a la derecha de esa dirección, y hacé clic.
200
Abajo aparece la respuesta: un número en verde (200 OK) y, debajo, texto con token y rol: "PACIENTE". No hace falta copiar el token a mano — Postman ya lo guardó solo para usarlo en los pedidos siguientes.
5

Probar un pedido que necesita el token

Carpeta Financiadores → Listar

Mismo mecanismo que el paso anterior: desplegá Financiadores, abrí Listar, apretá Send.

200
Lista de financiadores: IOMA y OSDE. Esto antes fallaba con 403 para un paciente — era un bug que ya se corrigió. Si te sigue dando 403, avisá.
6

Confirmar que los permisos frenan a un paciente

Carpeta Financiadores → Crear (admin)

Seguís logueado como paciente (paso 4). Ahora abrí Crear (admin) dentro de la misma carpeta y apretá Send — esa acción es tarea del administrador, no del paciente.

403
Sin permisos — y así tiene que ser. Un 403 acá es el resultado correcto: confirma que un paciente no puede crear datos de administración.
7

Ver "mis propias" coberturas

Carpeta Coberturas → Listar mis coberturas (paciente)

Abrí ese pedido y apretá Send. Juan Pérez es el paciente id 1 en los datos de prueba, y ese id ya viene cargado en el pedido.

200
Solo las coberturas de ese paciente. Este era el bug más importante que se corrigió: antes ni el propio paciente podía ver su lista de coberturas.
8

Registrar un paciente nuevo

Carpeta Auth → Registrar paciente nuevo

Este pedido no necesita token — cualquiera se puede registrar. Abrilo y apretá Send tal cual está.

201
{ idUsuario, idPaciente, mensaje: "Registro exitoso." } Si lo volvés a mandar sin cambiar nada, va a dar 409 (ya existe alguien con ese DNI) — es esperable. Para repetirlo, hacé clic en la pestaña Body de ese pedido y cambiá el número de dni y el email por otros.
9

Repetir todo, pero como administradora

Carpeta Auth → Login (administradora - médica)

Abrí ese pedido y apretá Send — reemplaza el token guardado por uno de administradora. Ahora abrí Usuarios → Listar (admin) y apretá Send: con este token sí tiene que andar, porque es información interna de administración.

200
Lista completa de usuarios. Si volvés a hacer login como paciente (paso 4) y probás este mismo pedido de nuevo, tiene que dar 403 — esa es la diferencia entre roles funcionando.
10

Registrar la consulta de un turno atendido

Carpeta Consultas médicas → Crear (desde un turno CONFIRMADO)

Seguís con el token de administradora del paso 9. Abrí ese pedido (ya trae idTurno: 3, un turno confirmado de los datos de prueba) y apretá Send.

201
Anotá el número id que te devuelve (es el id de la consulta) — lo vas a necesitar en el paso 11. Si volvés a mandar este mismo pedido, va a dar 409 (ese turno ya tiene una consulta cargada) — es esperable.
11

Cargar un diagnóstico

Carpeta Diagnósticos → Crear

Abrí ese pedido. Antes de apretar Send, hacé clic en la pestaña Body (debajo de la dirección) y reemplazá el número que acompaña a "consultaId" por el id que anotaste en el paso 10 (si es la primera vez que probás esto en tu base, puede que ya sea el mismo número y no haga falta tocar nada). Después apretá Send.

201
Anotá el id del diagnóstico — lo vas a necesitar en el paso 12.
12

Cargar el tratamiento

Carpeta Tratamientos → Crear

Mismo mecanismo: pestaña Body, reemplazá el número de "idDiagnostico" por el que anotaste en el paso 11, y apretá Send.

201
{ id, idDiagnostico, descripcion, duracion, estado: "EN_CURSO" } Con esto cerraste la cadena completa: Turno → Consulta médica → Diagnóstico → Tratamiento. Como prueba extra: hacé login como paciente (paso 4) y probá Diagnósticos → Listar — tiene que dar 403, es información solo para administración.

¿Querés probar otro pedido por tu cuenta?

En el panel izquierdo de Postman, dentro de la colección, hay una carpeta para cada módulo. El patrón es siempre el mismo: Listar trae todos, Obtener por id trae uno solo, Crear agrega uno nuevo, Actualizar edita, Eliminar da de baja (excepto Turno, que se cancela en vez de eliminarse). Solo hace falta tener sesión iniciada (paso 4 o paso 9) antes.

Si algo no anda

Antes de avisar, revisá esto — la mayoría de las veces es uno de estos casos.

No encuentro la terminal / se me cerró Se puede volver a abrir las veces que haga falta. Repetí el paso 1 (menú Terminal → New Terminal en VS Code) y después el paso 2 de nuevo.
Could not get response / ECONNREFUSED en Postman El backend no está prendido, o la terminal se cerró y se apagó. Volvé al paso 2 y fijate que la terminal siga abierta con la línea "Started BackendApplication".
BUILD FAILURE al escribir el comando del paso 2 Falta completar application.properties (base de datos, jwt.secret o mail). Avisá a Cami con el mensaje de error completo (podés seleccionarlo con el mouse en la terminal y copiarlo con Ctrl+C).
401 No autenticado Todavía no hiciste login, o pasaron más de 24hs desde el último. Volvé a mandar el pedido de Login (paso 4 o 9) — el token se renueva solo, no hace falta tocar nada más.
403 Sin permisos Tu sesión actual es de un rol que no puede hacer esa acción. Es el resultado correcto en el paso 6. Si te pasa en otro paso, avisá — puede ser un bug nuevo.
409 Conflicto Ya existe un registro con esos mismos datos (DNI, turno, etc.). Cambiá el dato en la pestaña Body del pedido (por ejemplo el DNI) y volvé a apretar Send.

¿Encontraste algo raro?

Pasale a Cami: el paso donde pasó y una captura de pantalla de Postman mostrando la respuesta completa (el número de código y el texto de abajo). Con eso alcanza para reproducirlo.
